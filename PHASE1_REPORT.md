## What was done

### M1 — Version Control & Safety Net
- Initialized a git repository at the project root (there was none — confirmed in `ARCHITECTURE.md` §1/§6.6).
- Committed the delivered prototype exactly as received as the baseline commit (`0874b3d`, 108 files), so "ImplantDesk 1.8" is now a real, addressable, revertible reference point.
- Set a repo-local git identity (not global) — required to commit at all in this environment.

### M2 — Data-Layer Test Harness
- Added Vitest (`vitest.config.ts`, jsdom environment, reusing the app's existing `@` path alias) plus `@testing-library/react`/`@testing-library/dom` as dev dependencies.
- Added `npm test` (one-shot, CI-friendly) and `npm run test:watch` scripts.
- Wrote `src/store/DataContext.test.tsx` — 12 tests exercising the `DataContext` action functions identified in `ARCHITECTURE.md` §6.5 as the highest-value, currently-unprotected logic (the code that encodes "every stock-changing action pairs a state update with a correctly-signed, correctly-typed audit movement," `PROJECT.md` §2):

  | Action | What's asserted |
  |---|---|
  | `adjustStock` | positive/negative deltas update `quantityOnHand` and produce a matching `adjustment` movement; quantity is clamped at zero, never negative |
  | `createPurchaseOrder` / `receivePurchaseOrder` | new POs start `draft` with zero received; a partial receipt moves status to `partially-received` and increases stock by exactly the received amount; a second receipt that completes the line moves status to `received`; over-receiving is capped at `quantityOrdered` |
  | `createLoan` / `returnLoanLines` | issuing a loan decrements stock and records a `loan-out` movement; a partial return moves status to `partially-returned` and restores stock only for the returned quantity; a return that fully accounts for the loaned quantity (returned + lost) closes the loan, and **lost quantity does not restore stock** (it produces a separate `lost` movement) |
  | `createSale` | total is computed correctly from line items; stock decrements; the movement `reason` differs correctly for a case-linked sale ("Used in patient case") vs. a direct sale ("Direct sale") |

- Along the way, noticed `*.tsbuildinfo` build-cache files had been swept into the M1 baseline commit (they predate this session, generated by the environment's earlier `tsc` runs) — added `*.tsbuildinfo` to `.gitignore` and untracked them. This is basic repo hygiene directly in scope for "version control safety net," not a separate initiative.

## What was intentionally not done

- **No architectural code changes** — Phase 2 (static-mock-lookup fix, business-rule centralization, ID hardening, `StatusBadge` type safety) has not started. This report only covers M1/M2.
- **`npm audit` reported 7 pre-existing vulnerabilities** (2 moderate — `react-router-dom`, a production dependency; 5 high — `brace-expansion` via `eslint`'s dependency chain, dev-only). These predate this session (present in the original `package-lock.json`) and were not introduced by M1/M2. Fixing the `react-router-dom` one changes a production dependency's resolved version, which is a judgment call outside this phase's scope — flagging it here rather than acting on it unilaterally. Recommend addressing as a short, dedicated task before or alongside Phase 2.
